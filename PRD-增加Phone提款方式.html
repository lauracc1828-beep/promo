一、需求背景

H5 取款页当前仅支持 CPF 单一提款方式。为支持巴西 PIX 场景下的多种收款标识（CPF、手机号等），并结合风控需要对不同方式设置开放门槛，需在后台提现管理页新增提款方式配置模块，由运营配置 H5 取款页可选的提款方式、展示顺序、启用状态及解锁条件。前台 H5 取款页原型已于前期完成，本期交付后台配置能力与相应的前台联动逻辑。

本期上线的提款方式为 CPF 与 PHONE 两种。本需求「增加 PHONE 提款方式」覆盖：后台提款方式配置（第四章）、前台 H5 取款页（第五章）、提现相关报表字段体现（第六章：会员提现审核、提现订单记录），以及提现资料绑定数量与唯一性校验（第七章）。

二、名词解释

术语说明
提款方式会员在 H5 取款页提现时填写收款标识的类型，对应 PIX Key 类型，如 CPF、PHONE。
CODE提款方式的系统标识码，与提款方式一一对应（如 CPF、PHONE），前后端交互及对接支付渠道时使用，语言无关。
解锁条件会员可使用某提款方式的前置门槛。会员满足条件后该方式方在前台展示并可选；未满足则前台隐藏该方式。
兜底方式状态恒为开启、解锁条件恒为「不限制」的提款方式，保证任一会员在任意状态下至少有一种可用方式。本期由 CPF 固定担任。

四、后台功能说明

4.1 入口与页面位置

在后台 商户财务配置 → 提现管理 页顶部页签中新增 「提款方式配置」 页签，位置固定为第二个，位于「提现通道配置」之后：

提现通道配置 ｜ 提款方式配置（新增） ｜ 提现条件配置 ｜ 提现等级配置 ｜ 其他提现配置

页签内容为单一列表（不含地区/商户筛选、大类分组头及额外操作按钮），沿用现有后台列表与弹窗样式。本期列表固定包含 CPF、PHONE 两条记录。

4.2 列表字段说明

列含义取值 / 展示
提款方式提款方式名称。CPF / PHONE，只读展示。
CODE提款方式系统标识码。CPF / PHONE，只读展示。
状态该方式是否启用。开关控件。开启 / 关闭。CPF 恒为开启且开关置灰不可操作。
解锁条件会员使用该方式的前置门槛，展示当前配置值。见 4.4；「已累计充值」时同时展示所配金额。
排序前台展示顺序权重。整数；数值越大越靠前。
操作行操作入口。「编辑」（打开编辑弹窗）。
ℹ️
列表按排序值降序展示；排序值相同按方式默认顺序（CPF、PHONE）。本期已按参照移除「图标」列。

4.3 编辑弹窗——字段规格

点击行「编辑」打开弹窗，标题「编辑」。字段规格如下（含义 / 控件 / 必填 / 输入要求）：

字段含义控件必填输入要求 / 说明
提款方式方式名称。文本框（置灰只读）—带出当前值，不可编辑。
CODE系统标识码。文本框（置灰只读）—带出当前值，不可编辑。
排序前台展示顺序权重。数字输入框（含步进器）是整数，最小 0；默认初始值 0；数值越大越靠前。
状态是否启用该方式。开关（开 / 关）是默认沿用当前值。CPF 置灰锁定为「开」（见 4.6）。
解锁条件会员使用该方式的前置门槛。单选（Radio，6 选 1）是选项与 ⓘ 说明见 4.4；默认选中「不限制」；旁附 ⓘ 说明图标（悬浮展示选项说明）。CPF 整组置灰锁定为「不限制」（见 4.6）。
累计充值金额「已累计充值」门槛的金额阈值。数字输入框是*仅当解锁条件 =「已累计充值」时显示，默认初始填入 0；有效值 1–1000。校验与提示见 4.5。

*「累计充值金额」为条件必填：仅在选中「已累计充值」时出现并要求填写；其余解锁条件下该字段隐藏、不参与校验。

弹窗底部为居中「确定」按钮；点击右上角「×」或遮罩关闭不保存。

4.4 解锁条件选项说明

解锁条件为单选，共 6 项，默认选中「不限制」。字段旁 ⓘ 图标悬浮展示以下说明（浮层原文）：

选项说明（ⓘ 浮层原文）
不限制表示该提现方式不受限制；
首充表示用户须完成首充，方可显示并使用该提现方式；
充值2次表示用户须完成2次充值，方可显示并使用该提现方式；
充值3次表示用户须完成3次充值，方可显示并使用该提现方式；
CPF首提成功表示用户须至少使用CPF 完成一次成功提现，才能显示并使用该提现方式。
已累计充值用户在指定商户或平台下的充值成功金额总和（不包括退款或失败交易）。

「CPF首提成功」作用于非 CPF 方式（如 PHONE）；CPF 自身解锁条件已锁定为「不限制」，不涉及该项。

4.5 校验规则与错误提示

「累计充值金额」仅在解锁条件 =「已累计充值」时参与校验，默认初始填入 0，有效值 1–1000。字段下红字为即时校验（输入 / 失焦时触发），顶部 toast 于点击「确定」时触发。各状态文案如下：

场景触发时机字段下红字（即时）顶部 toast（确定时）
占位（字段为空未操作）—输入框占位：输入金额数值大于0，最大数值为1000
清空后失去焦点失焦 / 确定请配置正确金额数值累计充值金额必须大于0
填 0 或 < 1输入 / 失焦 / 确定请输入大于等于1的数值累计充值金额必须大于0
> 1000输入 / 失焦 / 确定请输入小于等于1000的数值累计充值金额必须小于等于1000

校验不通过时输入框标红并拦截保存。空值与 0/<1 的字段下红字文案不同：空值为「请配置正确金额数值」，0/<1 为「请输入大于等于1的数值」。

4.6 CPF 兜底方式规则

CPF 固定作为兜底方式，以保证前台永远至少有一种可用提款方式：

  • 列表与编辑弹窗中，CPF 的状态开关置灰锁定为「开」，不可关闭。
  • CPF 的解锁条件整组置灰锁定为「不限制」，不可编辑。
  • CPF 仍可编辑排序。

CPF状态：开（锁定）解锁条件：不限制（锁定）

其余方式（PHONE 等）状态与解锁条件均可自由配置。由于 CPF 恒为「开启 + 不限制」，任一会员在任意状态下前台至少展示 CPF，从机制上杜绝「无可用方式」。

五、前台显示与联动逻辑

5.1 展示与可用性判定

H5 取款页「提款方式」区域根据后台配置动态展示可选方式，判定规则如下：

  1. 展示条件：某方式需同时满足「状态 = 开启」且「当前会员已满足其解锁条件」，方在前台展示并可选。
  2. 未解锁处理：不满足解锁条件的方式直接隐藏（不置灰、不占位）。
  3. 展示顺序：已通过判定的方式按排序值降序横向排列；默认选中排序最靠前的一个。
  4. 字段联动：选择不同提款方式时，下方对应的收款标识输入字段随之变化（如 PHONE 方式展示「手机号」字段）。此为前台既有交互，本需求不改动。
  5. 兜底保证：因 CPF 恒为「开启 + 不限制」，前台至少展示 CPF，一定存在可选方式。
ℹ️
前台各提款方式的按钮文案直接取 CODE（CPF、PHONE），语言无关，无需本地化。

5.2 提款信息填写、保存与回填

会员选择提款方式后需填写该方式对应的收款信息。字段构成：CPF 方式含「姓名、CPF ID」；PHONE 方式含「姓名、手机号、CPF ID」。规则如下：

规则说明
全部必填所选提款方式对应的全部字段均为必填，缺项不可提交提款。
首次保存时机会员此前未保存过提款信息时：提款成功后才将本次填写的信息保存至该会员的提款信息；保存后用户不可自行修改。
失败不保存首次填写的提款信息若提款不成功，则不保存；下次进入仍需手动填写。
已保存回填锁定会员此前已保存过提款信息时：提款页自动填入已保存信息且不可修改。
部分保存此前仅保存过部分字段时：已保存字段自动填入并锁定不可改，未保存字段需手动输入；本次提款成功后，新填写的字段一并保存并锁定。

筛选项规则

七、提现资料绑定数量与唯一性校验

为防止同一提现资料被多个会员共用，新增「提现资料可绑定会员数量」配置及配套唯一性校验。仅对 CPF、PHONE 两类提现资料生效。

7.1 后台配置（提现管理 → 其他提现配置）

在「提现管理 → 其他提现配置」页新增配置项，与既有「开启玩家首次提款信息绑定」开关并列，底部「保存 / 重置」：

字段含义控件必填输入要求
相同提现资料可同时绑定会员数量同一 CPF / 手机号最多可绑定的会员数量上限。数字输入框是非负整数；0 表示不限制，≥1 为具体上限。非整数 / 负数拦截保存，提示「请输入不小于0的整数」。

7.2 唯一性校验规则

当某 CPF / 手机号已绑定的会员数达到上限（配置值；0 为不限制，即不做该校验）时，不允许再绑定到其他会员。以下三处均在提交 / 保存时校验并拦截：

场景校验与处理
客户端 · 取款页提交提现其他会员输入已达上限的 CPF / 手机号时，不允许提交提现并提示错误。
客户端 · 提款信息管理保存提交的 CPF / 手机号已被其他会员保存（达上限）时，不允许保存。
后台 · 会员详情修改提款信息填写的 CPF / 手机号已被其他会员绑定（达上限）时，不允许保存。

绑定释放

会员绑定后，若运营在后台「会员详情」手动删除或更换该会员的提款信息，则原 CPF / 手机号占用随即释放，可再次被其他会员绑定。

九、边界与异常处理

场景处理
运营尝试关闭 CPF / 修改 CPF 解锁条件控件置灰锁定，无法操作（见 4.6）。
非 CPF 方式全部关闭或均未被会员解锁因 CPF 兜底，前台仍展示 CPF；不会出现无可用方式。
理论极端：因历史数据 / 异常导致前台零个可用方式隐藏「提款方式」区并置灰「立即提现」按钮，提示「暂无可用的提款方式，请完成充值后再试或联系客服」（兜底防御，正常配置下不触发）。
解锁条件切换离开「已累计充值」隐藏并清空「累计充值金额」，不参与本次校验。
排序值重复相同排序按方式默认顺序（CPF、PHONE）稳定展示。
